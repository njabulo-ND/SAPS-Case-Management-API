# SAPS Case Management API

## Project Overview

The SAPS Case Management API is a backend service developed to support a mobile application used by police officers.

The system connects the mobile application with the SAPS employee and case databases. It allows verified officers to create accounts, authenticate themselves, manage their profiles, create cases, view assigned cases, and update case information.

The backend acts as the communication layer between the mobile application, the SAPS SQL Server database, and Firebase cloud services.

## System Architecture

The application follows this workflow:

        +----------------+

### SAPS Database

The SQL Server database stores permanent SAPS information:

- Employee records
- Officer details
- Case information


### Firebase

Firebase is used for cloud-based services:

- Employee authentication data
- User profiles
- Cloud accessibility for mobile users

- Verify officers against the SAPS employee database.

### Case Management

- Create new cases.

## Installation & Setup

Follow these steps to run the SAPS Case Management API locally.


## 1. Clone the Repository

Download the project from GitHub:

bash
git clone <repository-url>

Navigate into the project folder:

cd SAPS-verification


2. Create a Virtual Environment

Create a Python virtual environment:

python -m venv myvenv

Activate the virtual environment:

Windows (Git Bash)
source myvenv/Scripts/activate
Windows (Command Prompt)
myvenv\Scripts\activate



3. Install Dependencies

Install all required Python packages:

pip install -r requirements.txt



4. Configure Environment Variables

Create a file named:

.env

inside the project folder.

Add the required configuration values:

DB_DRIVER=ODBC Driver 17 for SQL Server
DB_SERVER=your_server_name
DB_NAME=your_database_name
DB_USERNAME=your_database_username
DB_PASSWORD=your_database_password

FIREBASE_CREDENTIALS=path_to_firebase_credentials_file


5. Firebase Configuration

Download the Firebase Admin SDK credentials file from Firebase Console.

Place the JSON credentials file inside the project folder.

Update the .env file:

FIREBASE_CREDENTIALS=firebase_credentials.json

Important:
Never upload the .env file or Firebase credentials JSON file to GitHub because they contain sensitive information.

6. Run the Application

Start the Flask API:

python api.py

The API will start running on:

http://127.0.0.1:5000

# API Documentation

The backend exposes REST API endpoints that allow the mobile application to communicate with the SAPS database and Firebase services.

The API contains two main resources:

- Employee Management (`/employees`)
- Case Management (`/cases`)


# Employee Management API

## Endpoint
/employees


This endpoint handles employee verification, authentication, filtering, and account setup.


## GET Requests

The GET request uses the `action` parameter to determine the operation.


### 1. Verify Employee

Checks if an officer exists in the SAPS employee database.

If the employee exists:

- Retrieves employee information.
- Creates an employee profile in Firebase.
- Allows the officer to continue with account setup.


Example:


GET /employees?action=verify&id=employee_number



---

### 2. Employee Login

Authenticates an employee using their Firebase profile.

The API:

- Retrieves employee details from Firebase.
- Compares the provided password.
- Returns employee profile information if successful.


Example:


GET /employees?action=login&id=employee_number&password=password



---

### 3. Filter Employees

Searches employees based on rank and case type.

Used when assigning cases to suitable officers.


Example:


GET /employees?action=filter&rank=Detective&case_type=Theft

---

## POST Requests

Used for employee account setup.


### Add Employee Password

Allows a verified employee to create a login password.

Example request:

{
    "employee_id": "12345",
    "password": "password123"
}

The password is stored in the employee Firebase profile.


# Case Management API
## Endpoint
/cases


This endpoint handles all case-related operations between the mobile application and the SAPS case database.

The API allows officers to:

- View available cases.
- View cases assigned to them.
- Create new cases.
- Update case information.
- Assign cases to officers.


# GET Requests

The GET request uses the `action` parameter to determine the operation.


## 1. Retrieve All Cases

Returns all cases stored in the SAPS database.

The response includes:

- Victim information.
- Statement information.
- Modus operandi.
- Date opened.
- P21 information.
- Case number.


Example:


GET /cases?action=case_list



---

## 2. Retrieve Assigned Cases

Returns cases assigned to a specific officer.

The API searches cases using the officer employee number.


Example:


GET /cases?action=detective_case_list&employee_number=12345



---

# POST Requests

The POST request is used to create new cases and update existing case information.


## 1. Create New Case

Creates a new case record in the SAPS database.

The request requires P21 information and victim details.


Example request:

```json
{
    "p21": {
        "crime_type": "Theft",
        "location": "Station"
    },
    "victim": "John Doe"
}

The API creates a new case and returns the generated case number.

Example response:

{
    "caseNumber": 10001
}
2. Add Investigation Diary

Updates investigation progress for an existing case.

Example request:

{
    "caseNumber": 10001,
    "investigationDiary": {
        "progress": "Interview completed"
    }
}
3. Add Modus Operandi

Updates the crime method information for a case.

Example request:

{
    "caseNumber": 10001,
    "modusOperandi": {
        "description": "Entry through damaged window"
    }
}
4. Add Statement Form

Updates victim or witness statements linked to a case.

Example request:

{
    "caseNumber": 10001,
    "statement": {
        "statement": "Witness statement details"
    }
}
5. Assign Case To Officer

Assigns a case to a specific SAPS officer.

Example request:

{
    "action": "assign",
    "case_number": 10001,
    "employee_number": "12345"
}

The API updates the assigned officer in the SAPS database.
```
